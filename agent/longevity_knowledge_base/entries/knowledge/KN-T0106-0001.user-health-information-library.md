# 用户健康信息库是什么

## 1. One-line Summary

用户健康信息库是用户自己的、可持续积累并由用户授权使用的个人健康信息外脑；它与保存通用长寿信息的长寿信息库分开治理。

## 2. User-facing Explanation

Congtie 有两个不同的信息基础：

```text
Longevity Information Library
= general, reusable, versioned information

User Health Information Library
= private, user-specific, permission-gated context
```

长寿信息库保存可供不同用户复用的通用长寿信息，例如健康寿命概念、身体系统、测量与干预背景、生活方式、证据说明、行动资源、进展与观点及安全边界。这里不得存放某个用户的性别年龄、身高体重腰围、检测报告、诊疗记录、标志物数据、穿戴设备记录或个人生活方式等个人健康信息细节。

用户健康信息库面向“这个用户”。可以把它理解为用户自己的个人健康信息外脑：在用户控制下持续积累性别、年龄、生育情况、身高体重腰围等基础背景，改善目标、全身健康标志物、检测报告、诊疗记录、穿戴设备数据、生活方式、测量干预和行动历史等信息。MVP 概念类别仍使用 profile、goals、biomarkers、reports、lifestyle、actions、conversations 和 permissions，帮助减少反复提供背景与整理记录的负担。测量干预在这里是信息类别，不授权自动生成临床干预。

这并不意味着 Congtie v0 已经建成电子病历系统。用户健康信息库不是 EMR，也不替代医院信息系统；目前也不意味着已经与各类穿戴设备、检测设备、医学实验室、医疗机构或测量干预服务商实现全面数据互通。本条目只定义概念与边界，不代表这些数据连接已经实现。

用户应控制本人的个人健康信息及其使用权限。产品原则和未来系统应支持用户查看、编辑、更正、导出、删除，以及授权或撤回授权共享和 Agent 使用；这不表示 v0 已全部实现这些功能。AI 只能使用得到明确授权的个人健康信息上下文，并受用途、安全和时间范围约束。个人健康信息不应被放进长寿信息库、用于隐藏商业定向，或自动变成医学结论。

用户主动上传或授权连接读取健康信息，目的是逐步形成更完整、可追踪的个人健康信息上下文。这一行为本身并不构成诊断或医疗授权。Congtie v0 不因用户上传健康信息而自动获得诊断疾病、计算疾病风险、制定治疗、个性化补充剂方案或个人长寿方案的权限。

## 3. Key Points

- 长寿信息库保存通用、可复用、版本化的长寿信息。
- 用户健康信息库保存个人、用户特定、基于权限的健康信息上下文。
- MVP 概念类别包括 profile、goals、biomarkers、reports、lifestyle、actions、conversations 和 permissions。
- 用户控制自己的个人健康信息及其使用权限。
- AI 只能使用得到明确授权的个人健康信息上下文。
- 用户健康信息库与长寿信息库严格分离。
- 存储健康信息不等于获得诊断或医疗决策权限。

## 5. Safety Boundary

本条目不得用于：

- 把个人用户健康信息写入长寿信息库条目；
- 声称 AI 对个人健康信息拥有默认访问权或可未经授权使用；
- 声称 Congtie v0 已与 EMR、医院、穿戴设备、检测机构或各种测量干预服务商实现全面互通；
- 将用户标志物数据、检测报告或其他健康记录自动转换成诊断、疾病风险分数或治疗计划；
- 声称 Congtie v0 已因信息存储或连接读取而获准生成用药、剂量、补充剂、营养、训练或个性化医疗方案；
- 在没有许可时共享或用于商业定向。
