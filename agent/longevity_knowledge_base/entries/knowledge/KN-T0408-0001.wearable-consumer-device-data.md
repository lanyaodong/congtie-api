# 如何理解可穿戴与消费级设备数据

## 1. One-line Summary

可穿戴设备给出的数字并不都由传感器直接测得；理解设备数据，第一步是分清哪些是 measured、哪些是 estimated、哪些是 inferred，并保留设备与算法上下文。

## 2. 三层常见设备数据

用户界面显示一个精确数字，并不表示它就是传感器直接测得的原始信号。设备可能直接采集 PPG 波形、ECG 电信号、加速度原始信号或皮肤温度信号，而心率、步数、睡眠时长、睡眠阶段、恢复状态等通常还经过算法处理。具体分类取决于设备实现，不能只根据指标名称判断。

### Measured / 传感器测得

设备传感器直接捕获的物理或生理信号，例如 PPG 原始波形、ECG 电信号、加速度原始信号、皮肤温度信号或气压。即使是“直接测得”，信号也可能受到剧烈运动、松动佩戴、接触状态、皮肤特征、环境光和设备位置影响；任何单一因素都不能被写成对所有设备通用的误差解释。

### Estimated / 算法估算

设备使用信号和算法估算出的指标，例如步数、心率或静息心率、睡眠时长、睡眠阶段、能量消耗，以及部分 HRV 或呼吸相关指标。估算值的有效性取决于指标、算法、设备、用户情境和验证研究。

### Inferred / 进一步推断

设备把一个或多个测量和估算指标组合成 readiness、recovery、body battery、sleep score、Stress Score 或类似分数。这些分数通常是平台自有算法输出，可能适合帮助用户观察模式，但不等于直接测量到“恢复”“压力”“情绪”或疾病状态。厂商原名 `Stress Score` 可以保留，中文可解释为“设备压力估算”或“设备推断压力指数”；它是算法代理信号，不是对压力或情绪的直接读取，也不是心理疾病诊断。

同一个界面可能同时展示三层数据。Agent 应保留厂商原始 metric name，并用准确中文说明其性质，不能把 estimated 或 inferred 改写成“已测得事实”。

## 3. 趋势有价值，但要先问“可比吗”

设备数据的价值常在于长期、相对一致的记录，但“有趋势”不等于“趋势一定准确”。解读前至少要核对：

- 是否是同一设备、型号、佩戴位置和指标；
- 固件、App 或算法版本是否变化；
- 佩戴时长和缺失数据是否明显不同；
- 指标名称、单位和计算窗口是否一致；
- 生病、旅行、轮班、训练负荷或生活环境是否改变。

在同一设备内观察趋势，通常比直接比较两个品牌的绝对分数更有意义，但仍需核验具体指标的有效性。换设备、换算法或换版本可能构成趋势断点，不能自动拼接或归一化。

固件、算法或 App 更新可能改变计算方式，形成与更换设备类似的趋势断点，应单独标记而非自动拼接。导出数据时，还需要确认是否保留原始指标名、单位、时间戳、时间窗口和缺失状态，还是被平台重新聚合、平均或重算。

## 4. Consumer Wellness 不等于 Medical Diagnosis

FDA 的一般健康设备政策区分了低风险 general wellness 用途与疾病诊断、治疗等医疗用途。设备可以支持日常活动、睡眠或一般健康习惯观察，但这不意味着其每项指标都已达到临床诊断标准。

例如：

- 设备推断压力指数（原始指标名可能为 `Stress Score`）不是心理疾病诊断；
- 设备 sleep stage 不是 PSG 的替代品；
- 心率或 HRV 的短期变化不能单独证明某种原因；
- 正常设备分数不能排除用户真实存在的严重症状；
- 异常设备分数也不能独立确诊疾病。

消费级设备的 SpO₂ 一般健康监测功能，与用于睡眠呼吸暂停筛查、诊断或临床监测的功能，在 intended use、验证和监管要求上不同。不能仅因界面显示血氧数字，就推断其具备临床筛查能力。

同一品牌、设备或 App 可以同时包含一般健康功能和受监管医疗功能。监管状态需要按具体功能、型号、软件版本、intended use 和司法辖区核验，不能只按品牌判断。FDA guidance 只代表美国语境；用户询问中国具体设备时，应实时核验 NMPA、设备正式说明、厂商注册信息、独立验证研究，以及当前型号和版本。

## 5. 产品页面能支持什么

厂商产品页、用户手册和 feature description 可以支持：设备声称提供什么功能、指标叫什么、如何佩戴、如何导出数据，以及厂商公开的算法或限制说明。

它们不能独立支持：

- 指标已经被外部验证为准确；
- 设备能够诊断疾病；
- 使用设备一定改善健康结果；
- 该品牌优于其他品牌；
- 用户应该购买该设备。

准确性、有效性和临床用途需要独立验证研究、监管材料和具体 intended use 支持。

本条不提供任何具体设备推荐。不得仅依据本条、厂商营销或未经独立核验的信息提供品牌排名或购买建议。未来设备比较与购买支持应进入独立 T07 商品/服务治理，核验具体型号、验证、监管、中国可用性、用户需要和商业关系，并保持不收礼、零佣金、零广告、零赞助。

## 6. 最少上下文补全

用户希望理解某个设备数字时，Agent 应先复用已有授权记录，再根据问题只询问最少的关键缺口：

- 设备、平台和指标的原始名称是什么？
- 这是传感器测得、算法估算，还是平台推断的分数？
- 日期、时间窗口、单位和佩戴完整性是什么？
- 最近是否更换设备、佩戴位置、固件或 App 版本？
- 用户关心的是单次异常、长期趋势，还是与实际感受不一致？

用户可以跳过任何问题。Agent 不应为了追求“完整”连续追问大量生活细节，也不应在本条基础上建立运行时问诊、提醒或设备购买流程。

使用设备数据前，应确认用户授权该数据来源和指标用于当前解读。未授权、授权过期或只允许存储的数据不得被调用作解读。

本条解释设备数据性质；Biomarker and Measurement Registry 未来可记录具体测量项目、来源、方法、单位和可比性要求。本用户知识条目不分配或展示 Registry 内部 ID。

## 7. Evidence Boundary

本条采用 `E3`，反映消费级设备验证研究和系统综述对不同指标给出的结果并不一致。某个指标在某款设备、版本、人群和研究条件下表现较好，不代表其他指标、设备或版本同样有效。

FDA guidance 支持美国语境下 general wellness 与 medical purpose 的监管边界，不验证具体设备准确性。同行评议综述支持“有效性依指标和情境而变”的结论，不支持品牌排名或所有设备通用的临床判断。中国设备的当前监管状态需要实时核验，不能从美国 guidance 外推。

## 8. Quick Filter / 快速辨识

看到设备分数或健康 App 结论时，可以先核查：

1. 这是传感器测得、算法估算，还是进一步推断？
2. 数据是否保留设备、指标、时间、单位和版本？
3. 当前说法来自独立验证，还是厂商自述？
4. 是否把趋势观察夸大成诊断、因果或治疗建议？
5. 是否通过品牌排名、购买链接或商业关系影响结论？

信息不足时，应进一步核查，而不是因为分数看起来精确就提高确定性。

## 9. Safety Boundary

Agent 不得：

- 把设备压力估算、睡眠评分、恢复评分或准备度评分当作临床诊断；
- 以设备分数替代用户感受、实验室结果或专业评估；
- 未经验证跨设备、版本和算法合并趋势；
- 从单次设备异常推断疾病或干预因果；
- 仅依据本条、厂商营销或未经独立核验的信息提供品牌排名、购买建议或佣金驱动推荐；
- 仅依据设备数据生成治疗、用药或个性化方案。

measured、estimated、inferred 的分层不能成为对功能医学检测、生物年龄测试、补剂、药物或其他干预的背书。设备趋势也不能被表述为临床监测数据，除非具体 intended use 和证据支持。

## 10. Agent Usage Notes

在 Founder 批准并通过独立发布流程后，Agent 可使用本条标注设备数据性质、整理 provenance、解释可比性和帮助用户准备最少必要问题。

使用设备数据前，Agent 必须核对用户对当前数据来源和用途的授权；未授权、授权过期或仅允许存储的数据不得用于解读。

遇到具体产品时，Agent 必须独立核验设备版本、metric definition、validation、regulatory status 和 commercial relationship。设备被收录、被用户使用或能归入某个长寿策略方向，都不代表 Congtie 推荐该产品。

主动补全上下文时，Agent 应优先复用已授权的 User Health Information Library，不重复询问已有信息；一次优先提出 1–3 个可能改变当前解读的关键问题，并说明为什么需要。用户可以跳过，未回复不等于正常或信息已完成。本条不实现自动问诊、reminder、scheduler、购买流程或 runtime。
